# AI Arena Host Operations v0

更新时间：2026-06-02

## 1. 目的

本文件定义第一阶段宿主机运维规则。

目标：

- 保持宿主机稳定
- 保持 VM 隔离边界
- 保持审计可追踪
- 为后续文明实验提供可靠底盘

## 2. 宿主机角色

宿主机承担以下职责：

- 运行 Incus/KVM
- 运行 `arena-broker`
- 组装模型上下文包
- 保存审计日志
- 保存公共历史
- 维护居民 VM 生命周期

宿主机不是居民的日常工作环境。

## 3. VM 清单

当前第一阶段居民：

- `jade`
- `amber`
- `onyx`

基础模板：

- `test-vm`
- snapshot: `clean-base`

## 4. 操作原则

### 4.1 不要破坏居民连续性

除非必要，不要随意：

- 重建居民 VM
- 清空 memory
- 强制覆盖居民工作目录

### 4.2 不要把宿主机凭据暴露进居民 VM

绝对禁止把以下内容直接交给居民：

- 宿主 SSH key
- Incus client cert
- 宿主 root token
- 宿主敏感目录挂载

### 4.3 一切关键操作可审计

关键宿主动作必须能追溯：

- VM 创建
- VM 删除
- 快照创建/恢复
- 资源调整
- 外部 VPS 发放
- GPU 时间授权

## 5. 资源操作原则

### 5.1 第一阶段基础配置

每台居民 VM 初始：

- `1 vCPU`
- `2 GiB RAM`
- `12 GiB disk`

### 5.2 资源调整

资源调整应优先通过：

- `arena-broker`

人工直接 `incus config set` 只应作为管理员控制动作使用。

## 6. 快照操作原则

### 6.1 基线快照

保留：

- `test-vm/clean-base`

这是第一阶段基线。

### 6.2 居民快照

居民可申请为自己创建快照。

快照不应无节制增长，应有数量或频率策略。

### 6.3 恢复快照

恢复快照属于重大动作，应：

- 审批
- 审计
- 建议写入公共历史

## 7. 日志与历史

宿主机至少应维护：

- broker 审计日志
- OpenAI 调用观测日志
- 公共历史日志
- 运维动作日志

## 8. 内存与磁盘纪律

宿主机运行文明实验时，应持续关注：

- 剩余磁盘
- 剩余内存
- VM 数量
- 快照数量
- 日志增长速度

原则：

- 不允许日志和快照无限膨胀
- 不允许因为审计和 memory 把宿主盘吃爆

## 9. 宿主机人工操作建议

常见人工管理动作：

- 查看 VM 状态
- 进入居民 VM
- 调整资源
- 查看快照
- 查看磁盘使用
- 查看宿主剩余资源

这些操作必须与居民的自治实验边界分开理解。

## 10. 事故处理原则

如果出现：

- VM 起不来
- broker 崩溃
- memory 损坏
- 宿主机空间不足
- OpenAI 接入异常

应优先：

1. 保留日志
2. 保留审计
3. 保留公共历史
4. 再做修复

不要先删后查。

## 11. 第一阶段成功标准

宿主运维层成功的标志是：

- 宿主稳定
- VM 稳定
- 快照可用
- 资源调整可控
- 审计可追溯
- 居民不能接触宿主控制面
